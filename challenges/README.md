## 📁 Organization

Each challenge has its own directory, identified by its unique challenge ID.

Each challenge directory normally contains:

- **`README.md`** — The official challenge statement, requirements, topics, deadline, and instructions.
- **`starter.py`** — A starting file containing relevant setup or TODO instructions without providing the complete solution.

Additional files may be introduced when they serve a clear learning purpose.

## 🧭 How to Use This Directory

1. Open the relevant challenge's README.
2. Read the problem statement, requirements, deadline, and challenge rules.
3. Open its starter file and follow the instructions.
4. Attempt the challenge independently before seeking external assistance.
5. Submit your work through the designated submission workflow.
6. Participate in the group discussion after the deadline.

## 🔒 Important Rules

- Always follow the instructions and deadline specified for each challenge.
- Do not publish unfinished solutions in this public repository.
- Submit your work through the designated submission workflow.
- Do not publish or share reference solutions before the designated discussion and review stage.
- Follow the [Challenge Guidelines](../docs/CHALLENGE_GUIDELINES.md) and [AI Usage Policy](../docs/AI_USAGE_POLICY.md).

## 🚀 Learning Philosophy

These challenges are designed to develop more than the ability to write code that runs.

The goal is to build problem-solving skills, understand why solutions work, practise debugging, and learn to explain programming decisions independently.

**Learn the concept. Attempt the problem. Explain your reasoning. Improve through discussion.**
